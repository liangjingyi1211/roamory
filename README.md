# Roamory

Roamory 是一个结合 AI 旅行规划、Google Maps 与个人旅行日记的 Web 应用。输入目的地、旅行日期和偏好后，系统通过 Google ADK 协调景点、餐饮和住宿 Agent，结合 Google Places 返回的真实地点信息生成每日行程，并支持手动调整、AI 局部修改和图文记录。

## 项目介绍

### 主要功能

- **AI 行程规划**：根据目的地、日期、兴趣、饮食偏好和旅行节奏安排景点、餐饮与住宿。
- **每日行程管理**：通过横向 Day 日历切换日期，查看当天时间线；支持添加、替换、删除地点、调整顺序和编辑时间。
- **地图与地点详情联动**：桌面端左侧为 M1 Google Maps 与 M2 地点详情，右侧为日历、时间线和 AI 行程助手。点击地点卡片或地图 Marker 可查看对应地点。
- **AI 局部修改**：支持替换地点、增加安排和重新规划指定日期。
- **历史行程**：通过“我的行程”查看并继续编辑已保存的旅程。
- **图文旅行日记**：在地点卡片上记录文字并上传图片，在“我的旅行日记”中浏览和编辑。
- **本地持久化**：行程、日记和上传图片保存到 SQLite，重启后可以继续使用。

界面保留 Premium Blue 风格，并适配桌面及移动端。当前不提供交通路线规划、交通耗时计算或完整费用估算；建议时间也不代表地点开放时间已经验证。

### 技术组成

| 部分 | 技术 |
| --- | --- |
| Web 应用 | Streamlit |
| 自定义前端 | HTML、CSS、JavaScript |
| AI 工作流 | Google ADK、Gemini |
| 地点与地图 | Google Places API (New)、Google Maps JavaScript API |
| 数据校验与图片处理 | Pydantic、Pillow |
| 数据存储 | SQLite |
| Python 依赖管理 | uv |

前端为项目内置的静态组件，正常安装和启动不需要运行 npm 或单独构建前端。

## 安装与配置

### 1. 准备环境

- Python **3.11～3.13**，推荐 **Python 3.12**。
- uv，用于安装依赖和运行项目。
- 可访问 Gemini 和 Google Maps 服务的网络环境。
- Gemini API Key，以及已启用对应 API 和结算的 Google Maps 项目。

尚未安装 uv 时，可执行：

```powershell
python -m pip install uv
```

下载或克隆项目后，在终端进入项目根目录。下述命令均在包含 `pyproject.toml` 和 `streamlit_app.py` 的目录执行。

### 2. 安装依赖

```powershell
uv sync --locked --python 3.12
```

uv 会根据 `uv.lock` 安装依赖并创建 `.venv`。后续通过 `uv run` 启动，无需手动激活虚拟环境。

### 3. 创建环境配置文件

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

macOS / Linux：

```bash
cp .env.example .env
```

如果已有 `.env`，直接检查并补充配置，不要覆盖现有密钥。编辑项目根目录的 `.env`：

```dotenv
GOOGLE_API_KEY=你的_Gemini_API_Key
GOOGLE_GENAI_USE_VERTEXAI=FALSE
ADK_MODEL=gemini-3.5-flash-lite
GOOGLE_MAPS_API_KEY=你的_Google_Places_服务端密钥
GOOGLE_MAPS_BROWSER_API_KEY=你的_Google_Maps_浏览器密钥
```

| 配置项 | 用途 |
| --- | --- |
| `GOOGLE_API_KEY` | Gemini 模型调用使用的 API Key |
| `GOOGLE_GENAI_USE_VERTEXAI` | 使用 Google AI Studio 密钥时设为 `FALSE` |
| `ADK_MODEL` | Agent 使用的模型名称；模板值如不可用，请改为账号已获授权的模型 |
| `GOOGLE_MAPS_API_KEY` | 服务端检索真实地点使用的密钥 |
| `GOOGLE_MAPS_BROWSER_API_KEY` | 浏览器加载地图和地点详情使用的独立密钥 |

`.env` 包含私密配置，不要提交到代码仓库或分享给其他人。

### 4. 配置 Google Maps 权限

在对应 Google Cloud 项目启用结算，并配置以下权限：

1. **服务端密钥**：启用并允许访问 **Places API (New)**，用于目的地、景点、餐厅和酒店检索。
2. **浏览器密钥**：启用并允许访问 **Maps JavaScript API** 和 **Places API (New)**，用于 M1 地图和 M2 地点详情。
3. 为浏览器密钥设置 HTTP Referer 限制，本地开发允许以下来源：

```text
http://localhost:8501/*
http://127.0.0.1:8501/*
```

服务端与浏览器必须使用不同的密钥。浏览器密钥属于客户端配置，应通过网站来源和 API 范围限制保护；更换访问域名时，需要同步更新允许的网站来源。

未配置有效的服务端 Places 密钥时，系统无法完成真实地点检索。未配置浏览器密钥时，地图和官方地点详情不可用，但仍可查看已有行程时间线和进行手动编辑。

## 启动项目

在项目根目录运行：

```powershell
uv run --env-file .env streamlit run streamlit_app.py
```

浏览器打开：**http://localhost:8501**。

停止服务时，在终端按 `Ctrl+C`。再次使用时，重新运行上述启动命令即可，已保存的数据不会因正常重启而丢失。

## 使用指南

### 创建旅程

1. 打开首页，在新建旅程表单中填写目的地城市及国家、开始和结束日期。
2. 根据需要填写兴趣、饮食偏好、旅行节奏及抵达或离开等补充说明。
3. 提交并等待行程生成。生成过程需要调用模型和地点服务，耗时取决于行程长度及网络情况。
4. 进入行程页面后，点击 Day 按钮查看对应日期的安排。

### 查看地图与调整行程

- 点击时间线中的地点卡片，在 M1 定位对应地点，并在 M2 查看详情；地图 Marker 也支持地点选择联动。
- 使用卡片上的操作按钮添加、替换或删除地点，以及编辑时间和调整顺序。
- 切换日期后，时间线与地图同步显示当天地点。
- 地图与详情依赖真实坐标及 Google Place ID；手动录入但缺少相关信息的地点可能无法显示官方详情。

景点游玩时间优先于默认三餐模板。生成行程时，若餐次与景点时段冲突，先搜索景点内部餐厅；只有 Google Places 的 `containingPlaces` 明确指向该景点，且来源营业时间覆盖完整用餐时段，才允许在游玩期间用餐，不额外延长游玩时长。无法确认内部用餐时，会搜索该景点附近 2 公里、必要时 8 公里范围的餐厅，并尝试安排一小时的外部错峰用餐。

错峰安排限制在早餐 05:00–11:00、午餐 11:00–15:00、晚餐 16:00–23:00 内，并避开其他景点。无法核实营业时间或没有可行时段时，餐次显示“待安排”及原因，景点时间仍保留。营业判断依据 Places 返回的常规周营业时间，未验证节假日临时调整，也未计算往返交通时间。无冲突餐次沿用原有检索和时间模板；手动编辑只更新本地行程和冲突提示，不自动调用 Agent 重排。已有行程不会因刷新自动重新生成。

### 使用 AI 行程助手

在行程内容底部输入修改需求，例如：

```text
把第二天午餐换成附近的日料，其他安排不变。
给第一天增加一个博物馆。
重新规划第二天。
把第二天午餐换成附近的日料，再给第三天增加一个博物馆。
换第一天早餐和晚餐，午餐保持不变。
```

尽量明确每项修改的日期、目标地点和需求。当前助手支持 `replace`、`add`、`replan` 范围的局部修改，一条消息最多包含 **5 项操作**，按叙述顺序执行，后续操作使用前面修改后的行程。所有操作通过校验后一次保存，任意一项失败或发生版本冲突，都不会保存本批修改。

同一槽位重复修改、整天重规划与当天局部修改混用、引用前一步新生成但无法明确定位的地点时，需要澄清或拆分发送。景点修改不会自动重规划餐饮和住宿，除非消息中明确要求。已有时间待安排提示可以保留，但新产生的明确时间冲突会阻止本批保存。删除地点和编辑具体时间可使用卡片上的手动操作。

### 查看历史行程

从首页进入“我的行程”，选择已保存的旅程继续查看或编辑，也可以返回首页创建新的旅程。

### 编写和编辑旅行日记

1. 在景点、餐厅或酒店卡片上点击“记录”或“编辑记录”。
2. 输入文字、上传图片，或同时添加两者；确认后点击保存。
3. 从首页进入“我的旅行日记”，可以直接查看记录及图片。
4. 点击记录标题旁的“编辑”按钮，修改文字、添加或移除图片，再保存。取消编辑不会改动已保存内容。

每条记录支持最多 **10,000 个字符**和 **6 张图片**，图片格式为 JPG/JPEG、PNG 或 WebP，每张不超过 **5 MB**。地点被替换或从行程删除后，原旅行记录仍保留在日记库中。

## 数据保存与备份

新安装默认将数据保存到 `data/roamory.sqlite3`。已有安装如果保留旧数据库 `data/travelmind.sqlite3`，且尚未创建新默认数据库，程序会继续使用原文件，无需手动重命名或清空数据。

如需指定数据库和日志位置，可在 `.env` 中增加：

```dotenv
ROAMORY_DB=data/roamory.sqlite3
ROAMORY_LOG_FILE=data/backend.log
```

日记图片与文字一同保存在 SQLite 中。备份时先停止应用，再复制**实际使用的数据库文件**；更换数据库路径会切换到另一份数据，不会自动搬迁原有记录。

当前项目没有账号系统和用户数据隔离，使用同一实例的访问者共享该实例中的行程与日记。

## 常见问题

| 问题 | 检查方法 |
| --- | --- |
| 模型调用失败或行程生成失败 | 检查 `GOOGLE_API_KEY`、`ADK_MODEL`、模型访问权限、配额和网络；查看终端及 `data/backend.log` 中的错误 |
| 地点检索失败 | 检查服务端 Maps 密钥、Places API (New) 权限及结算状态 |
| 地图显示但地点详情失败 | 浏览器密钥需要同时允许 Maps JavaScript API 和 Places API (New)，两者授权应分别检查 |
| 地图无法加载 | 检查浏览器密钥是否独立、允许的网站来源是否包含当前地址，以及浏览器能否连接 Google Maps |
| 重启后看不到旧记录 | 检查启动目录和 `ROAMORY_DB` 配置，确认仍指向原数据库，不要删除 `data/` |
| 默认端口被占用 | 在启动命令末尾添加 `--server.port 8502`，并同步更新浏览器密钥允许的网站来源 |
